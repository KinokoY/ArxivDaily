# 运行、状态与恢复

2026-10-07：新增 `workflow.mode=translation` 元数据双语模式（不读取正文）和 `translation` / `title_translation` 恢复阶段，见 [TRANSLATION.md](TRANSLATION.md)。`archive/papers.md` 是额外的可更新长期索引，包含全部已保存规则候选，首次收集日期按北京时间；历史 schema_version=1 状态可直接重建。索引由发布器白名单纳入状态分支，每日不可变快照继续保持不可变。空结果正常检查也会生成和推送无新增通知，仍须先持久化 sending 与共享配额。空结果通知不占“每日有论文的正常日报”名额，后续当天发现新论文仍可推送；失败/未知空通知不自动重复重试，下一次成功检查生成自己的通知。

`--promote` 只将此前确认轻量、尚无确认完整事件的论文晋升。对已确认完整内容的显式重投用 `--resend ID`，它复用既有正文总结，不重调用分析接口；新增的 resend 事件保留历史。投递专用恢复/重投仅需 SendKey；其他阶段只检查其实际所需角色的凭据。

HTML 优先路径不会以图注代替必要视觉阅读：关键图会关联同版本 PDF 的实际物理页并渲染，模型输入提供正文、图注与图片。rendered/prepared 表示材料准备完成，visual_evidence_used 仅在有效分析输出后登记。必要图无法定位或清晰读取时保持待恢复。

`state.json` schema_version=1；遇到未知版本或损坏 JSON 会停机并保留原文件。迁移需显式编写、验证迁移器，不能自动清空历史去重。`.run.lock` 与 Actions concurrency 共同防止并发；进程异常退出可能遗留锁。人工确认进程已结束后，仅删除该状态目录的 `.run.lock` 再运行，不能清空 state.json。

记录分离为 metadata/versions、规则命中、三态 decision、intended_tier、正文门禁、summary_validated、日摘要快照、实际通知呈现与 delivery event。轻量不保存摘要总结；已完整总结仅因微信长度变成链接时保留完整身份和证据。

每个阶段操作前保存 attempt_started 与次数，成功后保存验证结果。付费长文章的每次安全 usage 和每块验证证据都单独保存；重启后复用匹配原版本、内容与提示契约的块证据。筛选/正文/总结失败在恢复期内有限恢复，不转成 reject。默认同一失败阶段每 UTC 日最多恢复一次，各请求内部最多三次传输尝试；正文/核查/总结跨运行默认三次、最多十四天，超界报告人工操作需要。

采集检查点独立于后续模型和发送；全部分页完成才能推进完整采集时间。首次七天、以后最多十四天滚动窗口，以首轮下界约束。超过回看范围的缺口保存在 run.window.uncovered；用日期补采 dry-run 核查后再显式交付。

完整档每日默认五篇、上限十篇，同日恢复共享上限。入选超额转 light 并存 full_quota_overflow，正常以后不补总结。正文或总结失败保持 full 待恢复，成功的总结只恢复投递。已送论文的修订、模型或配置变化不会触发自动重推。

不可变快照 `archive/YYYY/MM/DD/<digest-id>.md/.json/.notification.md` 分别保存完整历史、条目与 hash/关联和实际发送正文。日期索引 `archive/YYYY-MM-DD.md` 可追加。恢复生成新快照，关联 recovery_of，不能改旧文本和 hash。每篇保留原投递链，混合多条旧链与新文时也不会重置旧链次数。

POST 前同步发布快照并检查公开地址，再发布 sending 与额度预留；任一检查点失败立即停止新的付费或发送操作。推送后远程状态写失败，下一运行看见 sending，按 unknown 处理，已消耗次数保留。queued 只证明平台受理，confirmed 来自已识别的微信执行成功结构；不承诺已读或 exactly-once。

未知和失败投递按原链最多三次、最多十四天有限补发，复用原总结。发送、恢复与合并告警共享每日最多五次发送预算；模糊超时也消耗一次。配额按实际发送时的配置日界计算。`query_counts_quota=true` 时为同轮查询保守预留额度；是否查询扣平台配额、真实日界和 wxstatus 格式仍需免费账号联调。

若存档发布或 attempt_started 检查点跨过发送日界，本轮暂缓 POST，已知尚未使用的预留额度会释放；后续运行复用成功结果。正常工作流在下午执行，此保护也覆盖午夜的手工运行。人工晋升的请求会持久保留直到完整投递完成，暂缓或失败不会被此前轻量确认吞掉。

超次数/过期的人工恢复入口是 `run --retry-stage STAGE --retry-ids ID...`。默认仅在隔离状态中验证；实发须同时显式 `--send`、凭据和同步 publisher。处理阶段重开有限尝试，保留旧尝试事件与成功缓存；投递阶段保留原链累计次数，只为指定 ID 追加有限人工额度。自动运行不因这些参数变化擅自重推已送论文。

`llm.max_run_cost` 默认关闭。开启后按配置单价估计已返回的本轮 usage，并在下一次请求前检查；用量缺失时停止新的收费调用。费用估计不是账单，阈值也不是服务端硬余额封顶：已经在途的一次有界请求仍可能越过阈值。模型、价格或端点改变须使用验证后的 custom 价目策略。

公开状态不含 raw全文/PDF/图像、API key、SendKey、readkey、Authorization、原始响应/异常或隐藏 reasoning。raw来源与必要页面只在本地 fixtures/sources 与 tmp；回放fixture为校准预期，不是API输出。失效 Secrets 在运行环境修复后重试相应阶段，不删除论文记录或修改历史快照。
