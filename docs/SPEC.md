## 1. 目标、范围与基线

为单一读者每天收集新 arXiv 论文，经规则初筛与 LLM 终筛，交付微信合并简报和公开仓库 Markdown 历史。完整档的中文总结必须来自论文内容理解；轻量档只交付英文标题和 arXiv 链接。初筛偏召回，终筛偏精度。

已确定：

- Python；通过 `arxiv` Python 库访问 arXiv API；GitHub Actions 标准 Ubuntu runner 每日运行，使用公开仓库的免费执行条件。
- 基于 MIT 的 [X-PG13/paper-digest](https://github.com/X-PG13/paper-digest)，固定基线 SHA `8906f9a12309956913eab29dade75c01cb7d0771`。保留许可和归属，复用外围模块并改造核心流程。[基线证据](research/base-projects.md)
- 公开代码、兴趣配置、非敏感状态、Markdown 日报；Secrets 保密。持久状态及归档使用专用 Git 分支，不能仅依赖 Actions cache。
- 每日北京时间 **15:17** 启动，允许调度延迟；手动运行、历史补采和独立论文 ID 回放可用。[运行与 API 事实](research/arxiv-actions.md)
- 当前工作区根目录非空且不是应用 Git 仓库。下一轮建议在 `C:/Users/24252/Desktop/ArxivDaily/app/` 创建基线 checkout，保留根目录 docs、skills 和 glossary；本轮没有 clone。全部临时、生成和最终工作文件都放当前工作区及其子目录。

首版是配置驱动的单用户批处理。GitHub Pages、交互网站、多用户、Zotero、多文献源、邮件备用通道不属于首版要求；关闭上游无关路径与工作流。GitHub Actions 的免费执行条件不表示 LLM API 无费用；用户未确认 50 元/月或其他固定月预算。

## 2. 兴趣与交付层级

| 兴趣路线 | 相关性要求 | 默认交付 |
| --- | --- | --- |
| 医学推理分割 | 医学影像中的隐含请求、医学知识或位置 / 空间推理与 mask 输出直接相关；允许监督方法 | 符合全文质量后完整档 |
| 医学分割的 DPO / RL / 拓扑目标 | 贡献直接涉及医学分割的偏好、奖励、结构有效性或诊断策略；不强并为语言推理分割 | 符合全文质量后完整档 |
| 通用推理分割 + RL / DPO | RL / DPO 是本方法或主要贡献，且有向医学 / 推理分割迁移价值 | 符合全文质量后完整档 |
| 传统分割 / SAM 的目标设计 | 实质 loss / objective / reward / 结构约束贡献，有理论依据且可迁移；仅加模块或涨指标不够 | 证据不足先 `uncertain`，有限全文核查；核实价值后才可完整档 |
| 通用、无 RL / DPO 的推理分割 | 有任务相关性，但不属于上述优先路线 | **仅轻量档** |
| 不相关 / 仅背景提及目标主题 | 主任务、贡献与兴趣不符 | 排除，不放进轻量清单 |

不把 `reasoning segmentation` 固定短语、理论关键词或 transfer 字样设为必需门槛。ARIADNE 的摘要用血管分割、DPO、RL 描述贡献；普通损失工作的理论 / 迁移也可能只在正文讲清楚。不同路线是 OR，重复论文只评一次并保留全部命中理由。[兴趣事实与同义词组](research/interest-profile.md)

完整档每天**通常 5 篇、最多 10 篇，不足不凑数**。工程默认 `full_daily_limit=5`，可配置至 10，硬上限为 10；所有恢复任务在同一交付日共享此上限。排序后超出当日完整额度的**已入选**论文转轻量档，不自动积压到下一日补总结。其内部原因保留为 `full_quota_overflow`。未处理候选、核查不确定、解析 / 总结失败和投递失败是恢复状态，不等同于额度超额。

轻量档只渲染**英文题目 + arXiv 链接**，不附相关理由、评分、摘要或伪装的内容总结；理由等留在内部状态。轻量档是独立交付，不能因为出现于清单就记作“已阅读全文”。完整档已总结而微信因长度仅显示链接的情况，是通知裁剪，不能改写业务档位或丢失已验证总结。

## 3. 采集与规则初筛

### 3.1 查询和字段

摘要关键词是唯一默认关键词字段：使用 `abs` 或本地 `Result.summary` 匹配；标题只用于显示与 LLM 信息输入。标题规则后续仅在用户明确开启时生效；正文关键词规则不启用，`all:` 不能被描述为全文搜索。

分类可配置、可扩展，接受文章任一交叉分类命中。工程初始 OR 范围：`cs.CV`、`cs.LG`、`cs.AI`、`eess.IV`，而不是 `CS/CV`；医学论文不要求 q-bio 分类。关键词组与布尔路线沿用 [兴趣报告](research/interest-profile.md)，开发时用代表回放和负例校准；组内 OR、组间按路线 AND、路线间 OR，支持摘要排除词。缩写完整词匹配、英文大小写不敏感、连字符 / 空白规范化，不用标题命中偷偷扩大规则结果。

### 3.2 兼容、分页、限速与日期

工程基线 Python 3.12、`arxiv==4.0.1`，开发时复核并锁定相容版本。必须使用 arxiv 4 API：`arxiv.Client(...).results(search)`，完整结果使用 `max_results=None`；不使用已移除的 `Search.results()`、`Result.download_pdf()` 或 `download_source()`。正文下载由独立模块实现。

所有日期查询转 UTC / GMT，日报与执行日使用 Asia/Shanghai。存首版提交时间 `published`、当前版本 `updated`、首次实际发现时间和版本 ID；不要把北京时间昨天等同于 arXiv 公布 / API 可见日。单客户端完整迭代分页，合计 API 请求至少间隔 3 秒、一次一个连接；不得并行绕过限速。

固定只取最新 100 条不合格。API / 应用容量不足、分页中断或结果上限触发时必须标记覆盖不完整，保留已经发现的论文并按日期 / 主题拆分恢复；不把未获取部分视为无匹配，也不推进完整采集检查点。API 总查询上限按官方文档处理，不把 `max_results=None` 当作无限服务容量。

### 3.3 初次、延迟可见与补采

- 首次自动运行回溯 **7 天**，记录启动时确定的初始采集下界。
- 后续每日带重叠 / 滚动回看，覆盖最多 **14 天**内的延迟可见文章和漏跑；不能只按已推进游标之后的 submittedDate 查新文。工程建议每次复查最近 14 天、同时受首次采集下界约束，去重后只处理新发现的基础 ID。
- 全部分页与采集状态持久化成功后才能推进对应窗口的完整检查点；采集成功独立于后续 LLM / 推送成功。
- 与上次完整采集的缺口超过 14 天，自动只恢复允许范围，明确报告未覆盖区间并提供人工日期补采入口，不冒充全量恢复。有限回看无法保证覆盖无限期审核延迟。
- 人工指定日期区间可以突破自动恢复上限；独立 ID 回放可以突破日期窗口。两者默认 dry-run，不发送真实通知、不覆盖正常送达记录；实际重投需显式操作。

## 4. 三态终筛、有限核查与两档去重

LLM 终筛输出严格业务结构：`select | reject | uncertain` 三态、兴趣路线、建议 `full | light` 档位、理由、摘要依据、不确定项，以及 RL / DPO 是否是本方法、理论 / 迁移证据是否充分。相关性分数可辅助排序，不能用单一词命中替代语义判断。

- `select`：值得交付；按兴趣路线、完整额度和正文质量决定档位。
- `reject`：有证据说明不符兴趣；不得以轻量标题绕过排除。
- `uncertain`：摘要不足以判断；与失败、拒绝、已入选不同。传统目标设计优先在有限名额内核查正文；核实为有价值才改为 select，证据不支持则 reject，正文仍不足则保持 uncertain。
- API 失败、空内容、损坏 JSON、缺字段、错误枚举、长度截断是**处理失败**，不是 reject 或 uncertain 的有效模型答案。有限重试失败后保存待恢复。

工程建议有限全文核查 `review_daily_limit=2`，名额可调整；使用同一正文质量门禁和总结角色，明确输出核实证据。未轮到或仍不确定的候选默认不推送；若显式配置展示，可放“待核查”分组且仍只有题目 / 链接，不能称为入选或完整总结。

去重主键为**基础 arXiv ID**，首版和修订版分别存版本信息。新论文正常只推一次，修订不重推。一次 run 多路线 / 多分类 / 多页命中只生成一条论文记录。同一基础 ID 的正常交付在两档间共享送达登记：

| 既有状态 | 正常后续运行 |
| --- | --- |
| 未送达且 select/full，正文或总结失败 | 继续有限恢复；成功后可进入当日完整额度 |
| 已轻量送达，包括普通通用非 RL 与完整额度超额 | 不自动补总结或晋升，不把它留作明日完整任务 |
| 已完整送达 | 不因修订、再次命中、配置 / prompt / 模型变化重新推送 |
| 已总结但推送失败 | 复用验证结果和原证据，只恢复投递 |
| 推送状态 unknown | 按第 7 节有限补发，不再次付总结费用 |

**工程建议的晋升政策**：轻量已送后只允许显式人工晋升 / 重投；以原基础 ID 的同一记录增加完整交付事件，保留此前轻量事件，不伪造新论文。普通 ID 回放仍默认 dry-run；变更配置不会隐式让历史论文重新付费或重复交付。可选“待核查”标题展示也记独立 preview 事件，默认不触发自动晋升；发布者需显式选择后续交付，避免破坏一次推送语义。

## 5. DeepSeek 两角色与内容质量

### 5.1 已选服务与工程参数映射

两角色默认均使用官方 `https://api.deepseek.com`、`deepseek-flash`；provider、protocol、model、effort、输出预算、超时、重试和图像能力分别配置，可独立更换。可以共用 Secret 引用，不要求两把 API key。

| 角色 | 用户确定的思考意图 | 当前官方参数映射 | 输入 |
| --- | --- | --- | --- |
| 终筛 | 中等 | `thinking.type=enabled`，`reasoning_effort=high` | 兴趣、摘要、标题、分类、规则命中信息 |
| 正文核查 / 总结 | 极高 | `thinking.type=enabled`，`reasoning_effort=max` | 合格正文、证据、必要图表与核查问题 |

**映射属于明确的工程选择**：当前 Chat schema 规范值是 none / low / high / max，medium 和 xhigh 兼容值均映射 high；因此用 high 表达中等，用最高预算 max 表达用户要求的极高，保留两角色差异。不能机械写 xhigh 后两角色都落 high，也不能把旧提问的 none/low 记为已确认。[官方 schema](https://api-docs.deepseek.com/api/create-chat-completion/)、[能力报告](research/deepseek.md)

终筛相对便宜主要因为输入少、结果短；不是因为采用另一单价更低模型或已确认低思考。工程建议 Chat Completions + JSON 输出，先做兼容与完成状态探测。工程起始输出总预算：筛选 16,384 tokens、总结 / 核查 65,536 tokens，可配置；这是包括思考消耗的容量保护，不是承诺每次用满，也不是可见六句字数限制。不足导致截断必须失败重试 / 调整，不能解析残片。

记录实际返回 model / fingerprint、usage 中输入、缓存、输出和 reasoning tokens，并依核查后的价目计算费用估计。JSON 模式只保障语法时还须做字段校验；不公开隐藏推理轨迹。费用阈值可配置，默认不虚构 50 元/月硬预算；额度耗尽或费用保护触发应保存未完成阶段，不伪装无结果或强行摘要总结。

### 5.2 正文质量门禁

工程建议优先结构化 HTML，不可用或质量差则 PDF 抽取。下载来源记录具体版本；不得只把 arXiv URL 发给 LLM 并假定模型已读全文，也不能向接口上传 PDF 后假定当前图片输入功能会自动解析整份 PDF。

正文被判为合格，至少需要：来源 / 版本可追溯；可定位主要方法与实验 / 理论论证；章节或 PDF 页码映射有效；主要阅读顺序可信，双栏、重复页眉、缺页、乱码、异常过短等没有使关键部分失真。应用必须记录门禁理由、阅读覆盖、来源类型、图表使用和缺失部分，不能仅靠总字符数判合格。

关键方法 / 实验信息因文字提取缺失时，读取可提取表格、图注，按需渲染清晰图表 / 关键页输入 Flash 并校验。图像支持不等于数字识别准确；看不清的数值不可补造。PDF 工具按许可与实际抽取效果选择；不能在 MIT 项目里无评估加入有不同许可要求的依赖。[正文与许可事实](research/arxiv-actions.md)、[视觉限制](research/deepseek.md)

长文超出单次输入容量，应分章节提取证据并聚合，保留方法、实验及结论关键段落；不能只截前 N 字 / 页却声称理解全文。参考文献可从理解输入中分离，但承载关键方法或实验的附录不能因位于后部直接丢掉。按需图表无法完整处理时保留待处理，或明确缺失且确认不影响结论；不得静默跳过决定性证据。

全文获取 / 抽取失败时保存待处理并有限重试，**不以摘要降级成为完整档**。可以先交付同批其他成功论文；失败文章不自动变轻量已送以清空失败队列，除非它原本属于用户允许的轻量路线。

### 5.3 总结与证据

每篇完整档显示英文题目、arXiv 链接与中文五段：背景一句、贡献一句、方法两句、实验一句、结论一句为目标；准确性优先，可以为证据清楚做必要小幅调整，不机械数句到损害内容。

- 背景：具体问题 / 限制；贡献：本研究新增的任务、机制、目标或证据。
- 方法：主要结构、优化目标 / 奖励 / 偏好、训练或决策机制；区分作者方法、baseline 与相关工作。
- 实验：保留重要数据集、指标数字、比较对象及适用范围，用简洁自然语言说明结果。
- 结论：能被论文支持的结论与重要限制；未报告的信息明确写“未报告”或“无法由已读取部分确认”。纯理论工作没有相应实验时据实说明，不虚构实验。

内部总结结构同时保存证据引用：具体版本 URL、章节、PDF 物理页码、图 / 表编号，以及支撑关键方法、数值和结论的定位信息。HTML 无页码时用章节 / 表号，不杜撰页码；PDF 页码注明按文件计数。模型解释必须与定位处一致，不把作者的 SOTA / 首次 / 泛化宣称当独立验证事实。公开 Markdown 日报、不可变发送快照和微信正文只展示帮助读者判断是否值得阅读的五段总结，不展示证据定位列表；内部证据仍用于质量校验和后续审计。

正文质量门禁、输出结构完整、结束状态正常、关键主张 / 数字有证据后才能提交为 `summary_validated`。无法验证的数字删除或明确缺失，无法验证核心贡献则不合格。摘要可以提供定位线索，但不能成为完整档唯一阅读材料；摘要改写 / 翻译不是验收通过。

## 6. 阶段持久化、归档与并发

工程默认专用分支名 `arxivdaily-state`，名称可调。状态版本化，原子提交小批检查点；日期报告与已验证总结一并保存，cache 仅加速可重建内容。分支历史可公开，不能写 SendKey、readkey、API key、Authorization、带秘密的 URL、原始含凭据响应或异常对象。

需要持久保存：

1. 运行 ID、UTC 窗口、当地交付日、完整 / 不完整采集覆盖、API 页 / 分片恢复信息。
2. 基础 ID、已处理版本、首次发现时间、分类 / 摘要、规则命中与配置 / prompt / model 指纹。
3. 筛选三态与档位意图、uncertain / 核查证据、排除理由；阶段成功和失败尝试分别记录。
4. 正文质量与来源 / 阅读范围、已验证总结及证据、usage / 费用估计；原始全文 / PDF / 图像不要求上传公共 Git 分支。
5. 合并日报 ID、稳定内容 hash、不可变发送快照的归档地址、每篇关联、通知实际呈现方式和非敏感投递事件。
6. 发送 / 告警 / 补发次数、配额日界、pushid、queued / confirmed / failed / unknown、最后尝试和下次恢复时间；readkey 不持久化到公共分支。

先保存采集，随后分别提交筛选 / 核查 / 总结结果，形成日报和发送快照，再发送；投递结果再独立提交。每次 POST 前必须先持久化 `attempt_started/sending` 意图、关联快照及本次发送额度预留；这不是平台 queued，若进程在 POST 后确认前崩溃，下次据此恢复为 unknown，保留已消耗尝试，不能当作从未发送而无限重发。若保存失败，停止新的付费或发送操作并暴露恢复状态；不能明知状态不可持久化仍继续产生大量不可追回副作用。收到有效 LLM 响应但检查点写失败可能再次付费，属于剩余边界，有限重试并在日志报告，不承诺完全消除。

工程建议日期索引 `archive/YYYY-MM-DD.md`，发送快照 `archive/YYYY/MM/DD/<digest-id>.md`。先提交快照、取得可访问公开 Markdown URL，再通知；同日重跑不得改写已经发送的快照，日期索引可以追加已明确标记的恢复事件。无可交付论文且无失败时可只更新机器状态，不发空简报。

整个定时 / 手动 / 恢复任务使用同一 concurrency 锁，避免两个 run 同时变更状态；失败重试读最新分支，不覆盖别的提交。专用状态分支触发应避免递归启动日报。人工 dry-run / 回放结果使用独立运行空间，不更新正常游标、日额度或已送登记。

## 7. 免费微信交付、容量与 unknown 恢复

Server酱 Turbo 首版必须在**免费账号**可用；不依赖新账号 7 天会员试用、付费卡片内容或订阅保留时间。正常每天合并发送 1 条 Markdown 日报：微信服务号通知 → 点击详情阅读完整段落 → 公开 GitHub Markdown 查历史。免费会话卡片仅显示标题是允许的体验；详情是短期阅读页，不能作唯一归档。[已核查服务事实](research/wechat-plan.md)

发送接口采用 runtime Secret 中的 SendKey，允许部署阶段由用户配置。应用发送、告警、重发统一计数，**不超过免费 5 条 / 日**；工程默认日界 Asia/Shanghai，可配置，实际服务日界与计数部署时核查。请求超时但可能已接受仍消耗一次应用发送预算，不假定未扣额度。当天正常日报、unknown 恢复合并成同一份逻辑简报；确需重复的传输尝试是恢复事件，不能改成逐篇通知。

同 run 状态查询独立有界，工程默认最多 3 次、有退避。查询是否占用发送额度尚未证实，不能声称查询无限免费；部署观察实际限制，若查询也扣额度则降低 poll / 预留额度并记录 unknown。不要把所有 GET 强制算作滚动 24 小时发送 quota，造成延迟后的次日正常日报被无根据阻断；可以另提供可调保守模式。

### 7.1 消息长度

官方页面正文上限 32 KB、title 32、short 64。工程默认正文限 **30,000 UTF-8 bytes** 留余量，配置值不得超已验证平台上限；不是 30,000 中文字。采用 Markdown，避开 HTML；正常标题用简短纯文本，降低计数歧义。

保存完整仓库日报后，微信体按以下顺序适配：

1. 保留完整档的五段总结，减少非必要元数据。
2. 缩短通知内轻量清单，余项在同一日报归档可读；通知明确剩余数量并提供存档链接。
3. 仍超长时按**完整论文边界**减少微信内展开项，这些论文以标题和链接引导到已保存的完整总结；不能半截切掉方法 / 实验 / 结论，也不能增加正常日第二条消息。

微信内只给链接不改变原论文的 `intended_tier=full` 或 `summary_validated`。状态独立记录 `rendered_inline_full` / `archive_link_only` 等实际呈现方式、archive URL 与投递结果，不能把生成了完整总结的记录降成无总结轻量后丢失身份。正常容量下完整段落应在 Server酱详情直接读；容量例外必须显式说明，完整五段内容留在公开日报，内部证据留在状态记录。

### 7.2 发送结果与重试

顶层 HTTP / 业务成功只证明进入异步队列，不证明微信发出，更不证明用户已读。以当前真实响应解析 queued，按返回 pushid 和内存 readkey 有限查询 wxstatus；识别已知微信成功、失败以及尚未执行。部署验证业务字段，不沿用只看 HTTP 200 即确认。

readkey / SendKey 均敏感：仅运行时内存，Secret 不出现在 config、公共状态、日报、日志、artifact 或带 query 的真实 URL。公共状态只写 pushid 等非敏感标识、结果和 unknown；跨 run 不因缺 readkey 去保存明文或添加新外部数据库。

少漏推优先，允许少数重复：

- 明确未接受或已确认失败：按有限重试和日额度恢复。
- 已入队但同 run 查询仍不确定，或发送超时可能已接受：保存 unknown，不立刻盲目高频重发。
- 下一次 run 仍 unknown 且无安全可用查询凭据时，允许有限补发，明显标注“补发，上一轮投递未确认”；复用旧已验证论文内容与证据，将恢复条目加入当日恢复分组，生成新的不可变发送快照并以 `recovery_of` 关联旧 digest，原快照及 hash 不改、按实际条目保存送达，且不重新调用总结。无新结果时也可只恢复旧简报；接受上一条其实成功造成重复。
- 工程建议每日报最多 3 次自动传输尝试（沿原交付链跨 run 累计，不因生成恢复快照重置），超界告警 / 人工恢复，不无限消耗免费额度。正常成功登记后不再自动重发。

不承诺 exactly-once、确定到达时间或已读回执。响应成功后状态写失败仍可能重复；恢复时保留 unknown，并以内容 hash 和已有归档识别同一简报。

## 8. 故障、资源与 Secrets

- 采集完整且无可交付结果：静默。不得把采集 / LLM / 费用保护失败当作空结果。
- 部分成功：先发送本批可用完整 / 轻量论文，保留其他失败阶段；恢复复用已经成功的阶段及投递状态。
- 整次失败 / 无法安全持久化 / 超界恢复：一个合并告警，受免费发送额度约束；通知服务本身失败或配额不足时保留状态、Actions failure 与 job summary，不假装告警送达。
- 每阶段有限超时与重试。工程起点：网络 / LLM 最多 3 次尝试、指数退避加抖动；正文 / 核查 / 总结的跨日恢复最多 3 次、自动最远 14 天，可配置。历史正常已送论文不因这些参数修改重投。
- 工程建议 workflow timeout 45 分钟、少量 LLM 并发；达到时间 / 候选 / token / 费用保护时做阶段检查点并报告剩余任务。窗口容量不足要拆分，不能为赶时限静默丢数据。
- raw 异常、request / response 日志、上传 artifact 均经过脱敏和 whitelist；秘密只通过 Actions Secrets 注入运行环境。试运行采用模拟凭据 canary 检查泄漏，真实密钥不进入聊天、公共仓库或回放结果。
- 上游 workflow 的 Pages 权限、离线翻译模型下载、反馈同步、定期维护等首版禁用；日报 job 仅为专用状态分支写入申请所需的 `contents: write`，不需要 pages / id-token 写权限。

可调默认不是业务新约束。实现时若默认资源限制无法完成代表场景，应调整其值或保留明确失败，不降低全文 / 证据质量。未使用的预算项不得默认开启另一项订阅、账户或服务。

## 9. 验收矩阵

以下按可观察结果验收，不要求测试镜像函数结构。离线 fixtures、来源固定样本和故障注入为主；真实 API / 微信投递须在下一开发对话准备完成并由用户配置 Secret 后做小规模验证，本轮尚未验证。

| 场景 | 验收结果 |
| --- | --- |
| 摘要不命中，只有标题命中 | 默认不进入规则候选；标题仍可展示 / 输入给已由其他规则取得的候选 |
| 交叉分类且 primary 不在范围 | 任一配置分类命中即可；同 ID 多分类只评一次 |
| 250 条候选、多个分页 | 后续页的有效论文出现；重复条目不重复评 / 推；分页失败没有推进完整检查点 |
| 论文 submittedDate 在已推进游标之前，之后才 API 可见且在恢复窗口 | 滚动回看发现并处理；首次 7 天下界正确 |
| 漏跑 10 天 / 20 天 | 10 天恢复允许范围；20 天只自动补最近允许区间并报告未覆盖部分，支持人工补采 |
| 2 / 8 / 13 篇已入选完整路线 | 不足不凑数；按默认 5 或配置至10选完整，其余轻量；没有明日自动完整积压 |
| 通用非 RL、强相关 reasoning segmentation | 只英文标题 + arXiv 链接，不下载全文来伪造完整档 |
| RL 仅出现在 baseline / 相关工作 | 不认作本方法 RL；由任务和真实贡献判断档位 / 排除 |
| 传统 loss 摘要未显示理论 / 迁移 | uncertain、有限核查；有证据才 select/full；不能靠 theoretical 字样直接通过 |
| 全文 404、双栏乱序、关键方法 / 结果缺失 | 正文门禁失败、待恢复；不使用摘要生成“完整”总结 |
| 关键实验只在图 / 表中 | 按需读取清晰图表并定位；无法读取时不编数字，必要时不通过门禁 |
| 长文关键结论在附录 / 后部 | 分段理解保留对应证据；不能前缀截断后号称全文已读 |
| JSON 坏、字段错、模型输出截断 | 不拒绝论文、不发残片；有限重试，保存失败阶段 |
| 论文未报告所问指标，或只有理论论证 | 总结据实标未报告 / 理论，不能凑出实验数字 |
| 已 light_sent 后下次再匹配 / 修订 / 改模型 | 不自动完整晋升或重推；显式人工晋升保留原事件 |
| 已 summary_validated 后推送失败 | 重试不再调用总结模型；证据和 usage 保留 |
| 平台 queued、wxstatus 空 / request 超时 | unknown 保留；下次有限补发标记，可能重复但不虚假 confirmed |
| 两个 run、推送后状态写失败 | 不并发覆盖状态；已知结果保存，丢失确认边界可重复且可识别 |
| 免费账号已过试用、正常日报与告警 / 重发 | 不调用付费独占功能；发送预算合计 ≤5/配置日界；查询独立有界且额度限制诚实记录 |
| 中文正文逼近容量 / 单篇过长 | 按 UTF-8 bytes 管理；不截半篇；档位、生成总结、通知呈现分别记录；完整存档可访问 |
| 无结果 / 部分失败 / 整次失败 | 分别静默 / 发可用论文保留待恢复 / 合并告警，不能互相混淆 |
| Secret canary 出现在请求错误或状态查询 URL | 公共状态、git history、日志、artifact、日报均无 canary / 明文秘密 |
| 独立 ID 回放旧论文 | 绕过日期窗口但默认 dry-run，不通知、不改正常游标 / 送达登记 |

代表回放：

- [LISA 2308.00692](https://arxiv.org/abs/2308.00692)：通用无 RL 的任务基准；预期 select/light，不能强行 full。
- [MediSee 2504.11008v2](https://arxiv.org/abs/2504.11008v2)、[PRS-Med 2505.11872v4](https://arxiv.org/abs/2505.11872v4)：医学推理任务候选，核查后可 select/full；训练方法不能写成 RL。
- [ARIADNE 2603.19169v1](https://arxiv.org/abs/2603.19169v1)：医学结构 DPO / PPO 路线；即使摘要不含固定短语也应召回，不混成语言 CoT。
- 合成负例 / 不确定例：普通 U-Net 加 attention 只有 Dice 提升；分割文章只在 related work 提到 RL；医学文本 QA 没有 mask；理论 loss 摘要遗漏论证。标签由真实任务与正文证据决定。

以上是独立校准集，**不要求这些旧论文出现在当日日报**，也不保证每篇未经正文门禁都最终完整推送。验收报告需要区分静态 / 离线通过与真实接口、免费账号端到端验证通过。
